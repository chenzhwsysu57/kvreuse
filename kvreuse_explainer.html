KV cache，就像模型的“阅读笔记”

大模型读过一段长文本后，会留下内部计算结果。下次继续对话时，不必从第一页重读，直接翻到书签处即可——这就是 KV cache 能加速生成的直觉。

真实任务，不是玩具例子

只换“怎么看”，不换“看什么”

每条数据都固定 shared block，只改变前面的视角，并确保正确答案真的随之变化。这样，才能测到模型是否重新理解了同一段内容。

只改变 PREFIX
视角 A · 支持
寻找支持“取消校服”的论据
视角 B · 反对
寻找反对“取消校服”的论据
角色改变 → 判断标准改变 → 正确答案也必须改变
SHARED BLOCK 始终一模一样
项目最终要回答

不是“能不能复用”，而是“何时可以放心复用”

01
正确性会掉多少？

以完整重算为基准，测量 reuse 后的准确率、概率和输出差异。

02
什么变化最危险？

角色、立场、评分维度或利益函数变化，哪一种最容易让旧记忆误导模型？

03
哪里需要重算？

是否只重算边界 token、关键 token 或部分层，就能修复理解并保留收益？

04
真的更快吗？

在不同 prefix / block 长度与模型大小下，测量真实端到端时间，而非只看理论省算量。

一句话总结

重复的文字，不一定意味着重复的理解。

KV reuse 想省掉的是重复阅读的成本；本项目守住的是：当上下文变了，模型仍然必须形成正确的新理解。

更少重复计算+不损害语义理解=可信的 KV Reuse
